# План ядра Commodore VIC-20 для Karabas Go / Mini / Mini G

Цель: Commodore VIC-20 (6502, VIC 6561 PAL / 6560 NTSC, два 6522, расширения RAM 3K–35K, картриджи, Mega-Cart, дисковод 1541 с D64, магнитофон 1530 с TAP) на платах Karabas (XC6SLX25, ISE 14.7). Основа — [VIC20Nano](https://github.com/MiSTle-Dev/VIC20Nano). Файлы идут через прошивку (OSD, `FL`, `F`, `img_sdc`): загрузчика и soft-CPU в ядре нет. Репозиторий `andykarpov/karabas-go-core-vic20`, публичный.

Мышь c1351, пэдлы, RS232 VIC-1011 на user port |
| MiST / MiSTer VIC20 | живые | та же машина MikeJ; загрузка через HPS / ARM. Для нас ближе VIC20Nano: ему уже нужен внешний µC, как нашей прошивке |

Ресурсы: VIC20Nano без C1541 входит в Tang Nano 9K (GW1NR-9, 8,6K LUT4), полностью — в Nano 20K. Оценка для XC6SLX25: **~5–7K LUT из 15K**, проверить в Ф0. BRAM: ПЗУ 20K + RAM 5,5K + C1541 (ПЗУ 16–32K, RAM 2K, буфер дорожки) ≈ 45–60 КБ из 104 КБ — если всё держать в BRAM, места мало; поэтому расширения и картридж выносим в SRAM.

## Решения

Пользователь (2026-11-11): делаем VIC-20 (после обзора MiniMig / VIC20Nano); репозиторий `karabas-go-core-vic20` (создал сам, публичный). Ответы на открытые вопросы (2026-11-11): ПЗУ Commodore — в репозитории и `.kg`; PAL по умолчанию, NTSC из OSD; монитор принимает 720×576p@50; второй дисковод не нужен (бэклог).

Предложение (ждёт подтверждения; пока работаем по нему):

1. **Основа** — VIC20Nano: `vic20.vhd`, `m6561`, `m6522`, `t65`, `c1541/`, `c1530`, `megacart` как есть в `src/rtl/`, правки для XST с пометкой `-- karabas:` / `// karabas:`, SV через sv2v. Обвязка MiSTle (`sysctrl`, `sd_card`, `mcu_spi`, `hid`, `osd_u8g2`, `flash*`, `loader_sd_card`, `dualshock2`, `ws2812`, `video_lcd`) не нужна.
2. **Имя** `vic20` (`vic20.kg`, папка `/vic20`).
3. **Память.** Основная RAM (5K + цвет), ПЗУ char / BASIC / Kernal, RAM и ПЗУ C1541, буфер дорожки — BRAM. Расширения $0400 3K, $2000 / $4000 / $6000 по 8K, картридж $A000 8K, Mega-Cart 2 МБ, буфер TAP — в SRAM (2 × 2M×8 = 4 МБ, контроллер как в nanomig). SDRAM не нужна.
4. **Видео** — как в апстриме: родная развёртка VIC (PAL 312 строк / NTSC 261) → `scandoubler` → 720×576p@50 (PAL) / 720×480p@60 (NTSC) на HDMI (Go — VGA). Клоки из 50 МГц через `kg_pll` / DCM: подобрать к 35,469 / 32,727 МГц (8 × частота пикселя VIC) или взять апстримные 35,775 / 32,94; PAL по умолчанию, NTSC — из OSD (решено 2026-11-11); перестройка клока или два набора CE на одном клоке — решить в Ф0. Монитор пользователя принимает 576p50. Центрирование, широкий экран — из апстрима.
5. **Дискеты** — C1541 на D64 через `img_sdc` (F-слот, чтение и запись, LED активности); D64 по умолчанию `/vic20/disk8.d64`. Второй привод (номер 9) не нужен (2026-11-11, бэклог), G64 — если понадобится.
6. **Лента** — TAP: `FL`-файл кладём в SRAM, `c1530` играет из неё по `LOAD` (автостарт, как в апстриме). Звук ленты — выключаемый.
7. **Загрузчики** через `FL` (`kg_mcu` ROMLOAD): PRG в BASIC-память (инжект + указатели BASIC, как в апстриме), CRT / PRG-картридж по адресу из заголовка (2000 / 4000 / 6000 / A000, A000 последним — автостарт), Kernal 8K (.bin), Mega-Cart (.rom, 2 МБ).
8. **Клавиатура, джойстик** — свой `vic20_hid.v` поверх `kg_mcu_hid`: HID-код → матрица VIC-20 (раскладку взять из `vic20_keymap.v`), геймпад → джойстик Atari (порт VIA1 / VIA2), мышь → c1351 / пэдлы, numpad-джойстик. Сброс — Menu+F12, как в других ядрах; RESTORE — отдельная клавиша (как в апстриме).
9. **Звук** — 6-битный выход VIC + звук ленты → HDMI / PCM5102 / сигма-дельта.
10. **ПЗУ Commodore** (char, BASIC, Kernal PAL / NTSC, 1541 DOS) — в репозитории и `.kg` (решено 2026-11-11, как в апстриме, кроме JiffyDOS). JiffyDOS / Dolphin / SpeedDOS — только файлом пользователя через `FL`.
11. **Свой верх платы**, общий код через `modules` (`kg_mcu`, `img_sdc`, OSD, HDMI, PCM5102), Makefile как у atarist / archie. Первым — Mini G, затем Go и Mini. Mini G2: T3 = 0 (SDRAM ~CS). Физический дисковод Go не подходит (1541 — IEC, не Shugart): выходы `FDC_*` = 0. RS232 VIC-1011 — на UART / ESP (позже, по желанию).

## Архитектура

```
 VIC20 (vic20.vhd) ├── T65 ── шина ── BRAM: RAM 5K + цвет, ПЗУ char / BASIC, Kernal (FL)
                   ├── extmem ── vic20_sram ── SRAM: расширения 3K + 3 × 8K, картридж 8K, Mega-Cart 2 МБ, буфер TAP
                   ├── m6561 ── scandoubler ── OSD ── HDMI / VGA
                   ├── звук VIC ─┬───────────────────────── HDMI / PCM5102 / сигма-дельта
 c1530 (TAP из SRAM) ────────────┘
 клавиатура / джойстик / пэдлы ── vic20_hid ── kg_mcu HID
 IEC ── c1541_sd (6502 + 2 × VIA, DOS ПЗУ BRAM, GCR) ── sd_lba / sd_rd / sd_wr ── img_sdc ── kg_mcu (file mounter)
 FL: Kernal, PRG, CRT, TAP, Mega-Cart ── kg_mcu ROMLOAD ── BRAM / SRAM
```

## Фазы

Ветка и один PR на фазу, слияние в конце фазы.

- **Ф0. Импорт и fit.** `upstream/` (VIC20Nano без правок), `src/rtl/` с правками XST, Gowin-примитивы → инферируемые RAM из `modules/rtl/mem`, sv2v для SV, Makefile, `core.json`, `make vic20-xst` (машина + C1541 + C1530). Выбор клоков. Готово, когда XST собирает без защёлок и с ≥ 2× запасом по частоте.
  **Итоги Ф0 (2026-11-11, ветка `f0-import`).** Апстрим 9089828 в `upstream/` (без других плат Tang и `.exe`), рабочие копии в `src/rtl/` (`vic20/`, `t65/`, `c1541/`, `misc/`, `sv2v/`, `karabas/vic20_core.vhd` — машина + C1541 + C1530 без платы, её же возьмут верхи плат). Правки `karabas:`: Gowin pROM / SDPB / DPB / SP / FIFO → `kg_sprom` / `kg_sdpram` / `kg_tdpram` / `kg_spram` / `kg_fifo` (задержка 1 такт, write first, как READ_MODE 0 / WRITE_MODE 00 Gowin); расширения RAM и RAM картриджа ушли из BRAM (40K) в `extmem` (верх даёт `i_extmem_en = 1`, память — SRAM); `via6522` C1541 переименован в `c1541_via6522` (у машины другая версия с тем же именем); счётчик 1 МГц C1541 — сигнал вместо переменной, читаемой вне `rising_edge`; `change_timer` с диапазоном и init 0 (integer без init + асинхронный сброс давал защёлку, Xst:3002); Altera `tap_fifo` удалён. `mist_sd_card.sv` и `scandoubler.v` через `src/tools/sv2v.sh`. ПЗУ — `src/rom/*.bin` + `.hex` (`tools/bin2hex.py`), взяты из MiSTer VIC20_MiSTer (`.mif`), CRC32 сверены: char 901460-03 83e032a6, BASIC 901486-01 db4c43c1, Kernal 901486-07 PAL 4be07cb4 / 901486-06 NTSC e5e7c174, 1541 325302-01 29ae9752 + 901229-06AA 3a235039. В апстриме DOS 1541 во флеше пользователя, у нас — BRAM 16K (`ext_en = 0`). NTSC Kernal пока не подключён (апстрим тоже даёт PAL Kernal обоим стандартам) — в Ф4.
  `make vic20-xst`: **5525 LUT (36 %), 1988 FF, 28 RAMB16 (53 %), 73,7 МГц** (нужно 35,5: запас 2,08×), защёлок нет; обрезки Xst:1710 / 1293 — только от постоянных входов (ds, NMI, RESTORE, ear, Mode T65). `core.json` — черновик OSD (слоты: F 0 Disk 8, FL 1 PRG, 2 Cartridge, 3 Tape, 4 Kernal; `index` у переключателей), order 24 (23 оставлен apple2).
  **Клоки (решено в Ф0, уточнено в Ф2).** C1541 считает 32 такта `clk_sys` на такт 1 МГц (как апстрим, где 1541 идёт на 35,775 / 32 = 1,118 МГц), поэтому один клок на всё. Сделано в Ф2 (`vic20_clk.v`): на каждый стандарт своя цепочка `DCM_CLKGEN` → BUFG → `PLL_BASE` ×20 (/20 `clk_sys`, /4 и /4 180° — ×5 для HDMI): PAL 50 × 61 / 86 = 35,465 МГц (−0,01 %), NTSC 50 × 36 / 55 = 32,727 МГц (точно); обе цепочки работают всегда, `BUFGMUX` выбирает (переключение из OSD без перезапуска PLL, машина сбрасывается). Отвергнуто: одна PLL от 50 МГц (VCO ≤ 1000 МГц у -2: PAL только 35,0 МГц, −1,3 %), DCM_SP → DCM (дрожание), одна PLL за мультиплексором (остановка `clk_sys` на время захвата). Видео: строка VIC удвоенная `scandoubler` (1136 тактов PAL = 31,2 кГц, 624 строки = 50,0 Гц; NTSC 1040 × 522, 60,3 Гц), пиксель HDMI = `clk_sys`.
- **Ф1. Симуляция.** Машина + модель SRAM: загрузка ПЗУ до заставки «CBM BASIC V2 … BYTES FREE», кадр в PNG; клавиатура; PRG-инжект; `LOAD"$",8` с D64 на модели `img_sdc`.
  **Итоги Ф1 (2026-11-11, ветка `f1-sim`).** Модель Verilator по схеме core-apple2: `src/sim/vhdl2v.sh` (ghdl `--synth` VHDL-2008 → один Verilog-нетлист `vic20_core`, Verilog-модули — чёрные ящики, `bb_comp.py`), `tb_vic20.v` (машина + модель внешней памяти 64K: чтение регистровое на `clk_sys`, запись весь p2, блоки `ram_ext_ro` не пишутся), `sim_vic20.cpp` (клавиатура-матрица по тексту, интерфейс SD как `img_sdc` для C1541, инжект PRG как в апстриме: байты через `conf_*`, затем $2D / $2F / $31 / $AE, кадр PPM и **текст экрана**, распознанный по пикселям через ПЗУ знакогенератора, `--expect`). `sim/run_boot.sh <опции>`. Скорость ~9 мс машинного времени в секунду (профиль ровный, потоки Verilator только замедляют), загрузка ≈ 2,5 мин, поэтому длинные прогоны — только с согласия пользователя.
  Проверено: загрузка до «**** CBM BASIC V2 **** / 3583 BYTES FREE / READY.» (1,5 с), PRG (`sim/mkhello.py`) в 1,2 с + `RUN` с клавиатуры → «HELLO VIC» по всему экрану (1,85 с, 5 мин). Пользователь выбрал только эти прогоны: расширения RAM через `extmem`, NTSC и `LOAD"$",8` с D64 (образ готов: `src/tools/mkd64.py`, `--d64`) проверяются на плате (Ф2 / Ф3) или моделью позже по просьбе.
- **Ф2. Mini G.** Клоки, SRAM, видео → HDMI со звуком, HID, OSD, ПЗУ, расширения RAM, PRG / CRT через `FL`. Первый запуск на плате.
  **Ход Ф2 (2026-11-11, ветка `f2-minig`).** Верх `karabas_minig_top.v`: `kg_mcu` (FL, OSD, HID), `vic20_sram` (расширения и картридж в SRAM, слоты по 3 такта), `vic20_loader` (PRG — инжект + указатели BASIC; картридж — блоки read-only, сброс на время загрузки, Eject; Kernal — conf $E000), `vic20_hid` (отчёт USB → матрица через `keymap` апстрима; F11 = RESTORE, в апстриме не был подключён — подключён к CA1 VIA1; заглушки «левый Shift» для клавиш, которых нет у VIC-20, убраны, цифровой блок даёт цифры), видео: `scandoubler` (параметры после sv2v переставлены — передаются по имени), его `vb_out` теряется (10-битный счётчик выборок, а в строке 1136) — вертикальное окно по счётчику строк; DE 912 × 576 (PAL) / 816 × 480 (NTSC), OSD по центру (геометрия из `sim/run_boot.sh --geometry`); звук VIC 6 бит → PCM5102 и HDMI 48 кГц. SDRAM не используется (NOP, T3 = 0). В ucf нельзя TIG между стандартами: каждый триггер за BUFGMUX тактуется обоими, TIG накрыл все пути. Сборка 26111101: 5638 LUT (37 %), 55 % слайсов, 25 RAMB16 + 3 RAMB8, все ограничения выполнены, запас 10 нс. Тесты iverilog `sim/run_loader.sh`, `sim/run_hid.sh` (секунды, проверены мутациями).
  **Плата (2026-11-11, Mini G, 26111101).** По HDMI 576p: «CBM BASIC V2 / 3583 BYTES FREE», клавиатура, PRG из OSD + RUN, RUN/STOP (Esc), RAM 8K → 11775 и 3K+24K → 28159 BYTES FREE (SRAM), автостарт картриджа $A000 (A0CBM) и Eject (Menu+E), звук VIC по HDMI (сопрано 200 → 315 Гц, как расчёт), PAL ↔ NTSC переключаются. Найдено: в NTSC картинка сдвинута — у апстрима PAL Kernal для обоих стандартов; 26111102 добавляет NTSC Kernal 901486-06 (свой ПЗУ, +4 RAMB16; Kernal из файла заменяет оба). Особенность раскладки апстрима (позиционная): символы, которые на ПК набираются с Shift, а на VIC без него (`+`, `:`, `*`, `=`), дают графические знаки VIC. Пользователь: переключатель в OSD. 26111103: `Keyboard` (индекс 12) Symbolic (по умолчанию: символ ПК = символ VIC, Shift ПК снимается, Shift VIC ставится по нужде) / Positional (апстрим); на плате оба режима проверены (`PRINT 12+30` → 42 / 1230, `"A:B*C@D()=E"`).
  26111102 на плате: NTSC (6560 + Kernal 901486-06) — экран на месте, PAL после переключения назад — тоже. Ф2 закрыта.
- **Ф3. Диск и лента.** C1541 на D64 (чтение, запись, смена диска, выбор DOS ПЗУ), TAP через `c1530`.
  **Ход Ф3 (2026-11-11, ветка `f3-disk-tape`).** Disk 8 (F, слот 0): `img_sdc` (`OUT_LATENCY 2`) прямо на интерфейс `c1541_sd` — как MiSTle `sd_card` апстрима (`sd_ack = sdc_busy`, байты стробами); монтирование = смена диска, размер 0 = нет диска, ≥ 333744 байт = G64 (апстрим), WP — переключатель OSD или образ только для чтения (`ENABLE_IMG_WP`). Лента (FL 3): `vic20_loader` кладёт .tap в SRAM с 1 МБ, `vic20_tape` подаёт его в FIFO `c1530` (свой слот чтения в `vic20_sram`), версия — байт 12. Клавиша PLAY хранится в `vic20_tape` (нажимается в конце загрузки, переключается Tape play, отпускается в конце ленты), а C1530 (у него только переключатель, и любой перезапуск возвращает STOP) догоняется раз в ~0,1 с. Звук ленты подмешан тихо. `tools/prg2tap.py` (лента формата Kernal из PRG), `sim/tb_tape.v`.
  26111104 на плате: `LOAD"$",8` + LIST (каталог тестового D64 верный), `LOAD"HELLO",8` + RUN, `SAVE"NEW",8` (файл записан в образ на SD, проверено чтением образа на ПК), лента: FOUND HELLO / LOADING / RUN. Ошибка: после выбора TAP лента стояла в STOP (пришлось нажимать Tape play) — в 26111105 клавиша PLAY хранится и навязывается C1530 (причина на плате не выяснена, исправление покрывает любую). 26111105 на плате: TAP выбран → `LOAD` → «PRESS PLAY ON TAPE / OK / FOUND HELLO / LOADING» без ручного Play (C1530 успел вернуться в STOP — ядро его догнало); каталог D64 с «NEW» прошлого сеанса на месте. Ф3 закрыта. 8163 LUT (54 %), 81 % слайсов, 33 RAMB16 + 7 RAMB8.
